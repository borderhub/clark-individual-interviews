# 分析範囲（ANALYSIS SCOPE）

クラーク高校演劇部・個人面談の分析における、対象・単位・手順の定義。

## 1. 現在のステータス

**初期設定のみ完了。分析は未着手。**

以下はいずれも **未実施であり、承認があるまで実行しない**。

- 文字起こし
- 話者推定・話者分離
- テーマ分析・コーディング
- 公開用出力の生成
- 動画のダウンロード

個人面談データの初期取扱区分は **すべて `pending`**。
`pending` のデータは **分析・引用・外部共有・公開をしない**。

## 2. 分析単位（三層）

個人面談の分析単位は、次の **三層** とする。

| 層 | ID | 定義 | 粒度 |
| --- | --- | --- | --- |
| 面談 | `interview_id` | 1回の個人面談 | 1人1回の面談セッション |
| 質問 | `question_id` | 面談で用いられた質問 | 質問文ごと（面談をまたいで共通） |
| 回答 | `response_id` | ある面談における、ある質問への回答 | `interview_id` × `question_id` |

- `response_id` は `interview_id` と `question_id` の組に一意に対応する。
- 集計は原則として **`question_id` 単位** で行う。
  **`interview_id` 単位の個人別集計は、共有・公開用成果物に含めない。**

## 3. 話者の扱い

- 個人面談では **話者分離（diarization）を前提にしない。**
- 面談者と生徒の区別が必要になった場合も、**まず質問ログ（question register）で処理する。**
  - 質問はあらかじめ `question_register` に登録されている。
  - 「質問文にあたる発話＝面談者」「それ以外＝生徒」という対応で足りるなら、
    音声的な話者推定は行わない。
- 質問ログで処理しきれない場合にのみ、話者の扱いを人間が個別に検討する。
  その場合も、話者IDを共有・公開用成果物に含めない。

## 4. 分析対象に含めるもの／保留するもの

| 対象 | 状態 |
| --- | --- |
| 面談動画・音声 | `pending`（権限・同意の確認待ち） |
| 面談の文字起こし | 未作成（同意確認後に検討） |
| 事前アンケートの **質問文** | 記録可（実回答と分離すること） |
| 事前アンケートの **回答** | **保留**。面談動画の同意とは別に確認するまで、分析対象に含めない |

事前アンケートには、氏名、呼ばれたい名前、悩み、検索履歴・メモ・SNSに関わる内容、
感情が強く動いた出来事、面談で話したいことが含まれる。
**CSVの内容を表示・要約・分析しない。Gitに追加・commitしない。**
`private/intake/` にローカル保管する。

## 5. 比較に関する方針

- グループセッション（`clark-group_session`）との比較は、
  **将来、別のprivate環境** で行う。
- 扱えるのは **双方の承認済み・非再識別・集計済み結果だけ**。
- 本リポジトリの生データを既存リポジトリへ **移動・複製・参照しない**。

### 解釈の前提

> [!IMPORTANT]
> **「個人面談＝本音、グループ＝建前」と解釈しない。**

個人面談とグループセッションの差異は、真偽や深度の差ではなく
**面談形式（設定・聴衆・応答相手）の違い** として記述する。
形式が異なれば語られる内容も異なる、という以上の含意を置かない。

## 6. 成果物の制約

共有用・公開用のいかなる成果物にも、次を含めない。

- 生動画、音声、文字起こし
- 事前アンケート回答
- 個別回答
- 時刻・タイムスタンプ
- 話者ID
- 個人別集計

共有の可否は [../governance/RELEASE_GATE.md](../governance/RELEASE_GATE.md) に従う。

## 7. 想定する作業順序（承認後）

各ステップは **前段の人間による承認を前提** とする。無断で先へ進めない。

1. 受け入れ記録（`intake_register`）
2. 権限・同意の確認と記録（`consent_scope_register`）— **人間の責任者**
3. 質問台帳の整備（`question_register`）— 質問文のみ、実回答と分離
4. 面談台帳の整備（`interview_register`）
5. 文字起こし（承認後）
6. 非再識別化
7. `question_id` 単位のコーディング・集計
8. 共有ゲート判定（`release_register`）
